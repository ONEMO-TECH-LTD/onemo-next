- But the task intent is to remove the hardcoded test asset reference. It still exists in EffectViewer.tsx. **Engineer needs to address the EffectViewer fallback** to fully close this task.

## KAI-4789 — Editor Camera Settings Tab + R3F Sync

**Verdict: PASS**

### What changed
1. New file `editor-camera.ts` — dedicated settings panel for editor camera (FOV, projection, near/far clip, clear color, grabpass, zoom sensitivity).
2. Settings previously in `editor.ts` (camera-related fields) moved to `editor-camera.ts`. Editor panel retains grid/snap/fog/skybox settings.
3. New `EditorCameraSettingsSync` component in StudioViewport.tsx — listens to `r3f:viewer:editorCamera*` events and applies FOV/near/far/projection changes to the R3F working camera.
4. `viewport-cameras.ts` updated to open the `editorCamera` tab instead of `editor` tab when clicking the camera settings button.
5. Panel registered in `settings-panel.ts` as `{ id: 'editorCamera', label: 'Editor Camera' }`.

### Event wiring verification
| Panel emits | Sync listens for | Handler |
|-------------|-----------------|---------|
| `r3f:viewer:editorCameraFov` | `r3f:viewer:editorCameraFov` | `handleFov` — validates >0 <180, perspective-only |
| `r3f:viewer:editorCameraNear` | `r3f:viewer:editorCameraNear` | `handleNear` — validates finite, >=0 |
| `r3f:viewer:editorCameraFar` | `r3f:viewer:editorCameraFar` | `handleFar` — validates finite, >0 |
| `r3f:viewer:editorCameraProjection` | `r3f:viewer:editorCameraProjection` | `handleProjection` — perspective<->ortho swap |

### Projection switching
- Ortho->Perspective: Computes equivalent FOV from ortho view height + orbit distance. Clamped to [1, 179] with fallback to 35. Preserves position + quaternion. Force-renders one frame with new camera. Calls `onCameraReplaced` to update bridge.
- Perspective->Ortho: Computes half-height from FOV + orbit distance. Preserves position + quaternion. Same render + bridge update pattern.
- Uses existing `onCameraReplaced` -> `emitBridge({ camera: nextCamera })` path, same as `CameraCommandController`. Consistent with codebase pattern.

### Removed settings — NOT a regression
Tonemapping and Gamma were removed from the editor panel. These are PlayCanvas-specific settings (`cameraEntity.camera.toneMapping` in `viewport-application.ts`). The R3F viewport handles tone mapping at the renderer level. Entity camera components still have their own tonemapping UI in `components/camera.ts`. Intentional removal.

### Cleanup hooks
All four event listeners are properly unbound in the effect cleanup return. `useEffect` dependency array includes `[camera, gl, scene, size, orbitControlsRef, onCameraReplaced]` — correct for the closures used.

## Notes (non-blocking)

1. **`handleNear` allows `near = 0`** (StudioViewport.tsx line 2195): `value >= 0` permits zero near clip on perspective cameras, which degrades depth buffer precision to near-useless. However, this matches the original settings panel config (`min: 0` in the attribute definition) — pre-existing behavior, not a regression introduced here. If this is a concern, a separate issue should address it with `min: 0.001` in both the panel config and the handler validation.

2. **`import.meta.env` build warning**: Harmless due to optional chaining, but could be eliminated by using Vite's `define` config to replace `import.meta.env.DEV` at build time, or by using a different dev-mode detection pattern for the chrome63 target. Low priority.
