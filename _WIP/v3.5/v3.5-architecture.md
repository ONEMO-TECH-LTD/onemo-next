# Magnetic Grid Lab v3.5 — Architecture

> Full-module catalogue of the grid-origin bench as it stands on branch `session62-task/grid-v3.5`.
> Every claim below was verified against the code at writing time. Provenance marks:
> **[DAN-RULED]** = a product value or behaviour Dan set (with date where recorded);
> **[ENGINEERING]** = a mechanism or default chosen by the engineer, open to Dan's calibration.

---

## 1. What the bench is

The bench is the admin surface for the magnetic grid engine: a page at `/effect-creator/grid-origin`
where a shape (preset, generated, or AI-cut from a photo) is laid over the fixed ONEMO magnet grid,
and the engine decides — live, per size — where magnets seat, which sizes in a band genuinely hold,
and how the grid centres on the shape. The engine descends verbatim from the 20-July v1 algorithm
(erode the shape by the safety padding, slide the grid underneath, keep the placement that seats the
most magnets) with Dan's later rulings and the proven speed work applied on top.

### The module protocol

Six layers, one direction of traffic, enforced by an executable guard (§6):

| Layer | File | May contain | May never contain |
|---|---|---|---|
| **SPEC** | `grid-origin-spec.ts` | Values only | Functions, arithmetic, policy |
| **COMPUTE** | `grid-origin-compute.ts` | Geometry and arithmetic | Product opinions, UI concepts |
| **LOGIC** | `grid-origin-logic.ts` | Policies (decisions over measurements) | Geometry of its own |
| **ENGINE DOOR** | `grid-origin.ts` | Wiring of spec+compute+logic; the one import surface | — |
| **UI BRIDGE** | `grid-origin-bridge.ts` | Shape preparation, display lists | Law values, policy |
| **SHELL** | `page.tsx` + `solve.worker.ts` | Drawing, controls, dispatch | Any computation or bare law value |

The page may import only from the engine door, the spec, and the ui-bridge. Modules never import
from the app. No file outside spec may write a released value as a bare number.

### 2.4 `grid-origin.ts` — the engine door

The one import surface. Re-exports all of spec, the display-safe compute pieces, and the
public logic types; wires everything in two functions.

**`GridConfig`** — the solve inputs: `pitchMM`, `paddingMM`, `flapMM`, `phaseStepMM`,
`forcePhaseMM` (manual calibration: seat exactly at this registration, no search),
`massDepthMM`, `plan`, `perimeterOnly` (default true), `circle` (judge against the analytic curve).

**`GridResult`** — what a solve returns: `anchors` (placed magnets), `flaps` (loose-material
points), `ok`/`issues` (legacy verdict — currently unconsumed), `pitchCentreMM`, `edgeRangeMM`
(pitch+min/max diameter — currently unconsumed), `lattice` (every position at the chosen slide),
`phaseMM` (the chosen slide), `panMM` (offset from the canonical slide), `spotRadiusMM`,
`segments` (the island/mass map the centring anchored on).

**`computeGrid(contour, cfg)`** — the solve (§3 walks it end to end). Note: its header comment
still says "on the 12mm increment" — stale; the ruled default is 1mm (§7).

**`BandSnapPoint`** `{sizeMM, count, sig}` — one holding size with its layout identity.
`sig` (internal `layoutSig`) = the magnets' relative arrangement + the pan class, so two sizes
with the same arrangement at the same registration count as one layout.

**`bandSnapPoints(sized, cfg, fromMM, stepMM)`** — walks every size of the band range
(`snapRange`: the band; above B5, up to the board span) at the snap step and keeps sizes that
hold (per `isHolding`). The band is a RANGE — fit is not monotone, every size judged independently.

**`fitSizeInBand(...)`** — the band snap: `ladder` = every DISTINCT holding layout, each at the
smallest size where it appears (sig-deduped, as honest as the free slider **[DAN-RULED]** "the
bands must be as honest as the free slider"); `pickIdx` = the landing pick, the smallest size at
the band's MAXIMUM seat count (**[DAN-RULED]** "the snap pick (smallest size at max count) is
correct behaviour"). Empty ladder → fallback: the size with the most seats, flagged by the shell
as "nothing fully fits — best seated shown".

### 2.5 `grid-origin-bridge.ts` — the UI bridge

Shape preparation and display lists; no law values (its one constant `FLATTEN_REF_MM = 250` is a
flatten resolution: curves are flattened as if cut at 250mm, then normalized, so the 0.05mm
manufacturing tolerance holds at every slider size).

| Export | What it does | Called by |
|---|---|---|
| `normBaseContour(vshape, maskH)` | Vector shape → mm contour normalized so longest side = 1 (scale-free), flattened at manufacturing fidelity | page (presets + AI Magic) |
| `normGeneratedRing(ring, imgH)` | Generated pixel ring → normalized y-up contour | page (generators) |
| `makeSizer(base, offsetMM)` | Returns mm-contour-at-any-size, applying the outline offset (grow/shrink via `insetRingMM`) | worker |
| `sizeRange(pad)` | The offered size range: 24 → board span + margin (420 at padding 12) | page slider limits |
| `FieldSpot`, `fieldSpots(grid, view)` | Every lattice position across the view as a drawable spot (radius = spot radius, held = a magnet seats there), re-anchored on a real answer point so the drawn field can't drift from the solve | page (Show lattice on) |
| `seatedSpots(grid)` | The seated spots alone | page (Show lattice off) |

The bridge also re-exports `computeGrid`, `GridResult` and `MagnetPlan` from the door for
consumers that only speak to the bridge.

### 2.6 `solve.worker.ts` — the off-thread solve

Pure dispatch, nothing computed. Receives `{id, base, offsetMM, cfg, mode, sizeMM, snapStep,
stepSel}`. Free mode → one `computeGrid` at the set size. Band mode → `fitSizeInBand` from the
band floor; the whole walk is **cached** keyed on everything except the selected step, so clicking
ladder steps re-uses it instantly. Replies `{id, model:{contour, grid, effSize, ladder, idx,
segments}}` (`segments` = `grid.segments`, one source). Errors reply `{id, model:null, error}`.
Stale replies are dropped by id on the page.

### 2.7 `page.tsx` — the shell

Draws and dispatches only (guard-checked: no geometry calls, no bare law values). Components:
`GridLab` (state + panel), `Stage` (the SVG canvas), `Slider` (range + typed number field),
`LabRow` (a control with its own enable checkbox — off drops the field from cfg so the spec
default rules), `Sec` (perf seconds, green, red past 2s), `Fold` (collapsible card), `Empty`.
Screen constants: `IMG` 1000 (source raster), `VP` 640 (stage px), `FIT` 0.86 (shape fills 86%
of the frame — the v1 camera: **the shape never moves or zooms; the grid scales under it**).

Canvas layers, bottom to top: panel ground → two-level mm rule anchored on the lattice (so line
crossings ARE magnet centres) → shape wash + cut line (light-on-dark palette in dark mode) →
segment islands (fill + solid outline + dashed island box + centre cross + `S1 · area · N◆`
label) with depth masses (dashed inner outlines + centre dots) → shape bounding box with mm on
each side → the spot field (faint = empty position, accent = seated) → the magnets (6/8mm bodies).

Gestures (manual calibration **[DAN-RULED]** "free mode + manual control"): drag pans the GRID
under the frozen shape (feeds `forcePhaseMM`), pinch scales the effect size, double-click returns
to the engine's automatic registration. px→mm uses the rendered size so gestures stay true on a
phone.

## 3. The solve pipeline, end to end

1. **Shape source** — Presets (baked vectors), Generators (blob/clover/daisy/pinwheel), or
   AI Magic (photo → u2netp background cut → traced outline, via v5.3.1's `prepareShaped`).
2. **Normalization** — the outline becomes a scale-free contour, longest side = 1mm, curves
   flattened at manufacturing fidelity (`normBaseContour` / `normGeneratedRing`).
3. **The page posts a solve** to the worker on any input change: config (only enabled dials send
   their fields), mode, size, snap step, selected ladder step.
4. **`computeGrid` per size**:
   - padding → spot radius (centre-measured); reach = spot + flap allowance;
   - seat test built (exact integer predicate + float prescreen; analytic for a true circle);
   - **island/mass map** measured once (§4);
   - the grid slides under the frozen shape across one 48mm period in `phaseStepMM` steps,
     **anchored on the canonical registration**: slide k=0 puts a grid line exactly on the box
     centre (odd-count parity) and the walk always samples the even-parity position too — the
     centred registrations are candidates at every size, never skipped;
   - each slide is scored: **most seats wins absolutely → least loose material (bucketed by the
     2mm tie range) → centring** — the seats inside the governing mass (smallest mass holding a
     seat, per logic's `centeringRef`) measured to that mass's deepest point; box centre as
     fallback;
   - **perimeter belt** (`applyCoverage`): with >4 seats, fully-surrounded interior nodes are
     dropped; magnet diameters assigned per plan.
5. **Band mode** (`fitSizeInBand`): every size in the band walked at the snap step; sizes that
   hold (≥1 seat, zero loose-material points at the flap dial) enter the list; the **ladder**
   dedupes to distinct layouts at their smallest sizes; the **pick** is the smallest size at max
   count; empty → best-seated fallback with the banner.
6. **Return + draw**: the model (contour, grid, ladder, index, segments) renders as §2.7's
   layers; the perf strip reports load / gen / cut / solve in seconds.

## 4. The segment & mass system (`safeSegments`)

One measurement answers "where can a magnet centre legally exist, and how is that area shaped":

- **Signed clearance mesh** — the (decimated ≤800-vertex) outline is sampled on a 2mm mesh, one
  number per point: distance to the cut line minus the spot radius (negative outside the shape).
  Positive = a magnet centre is legal there.
- **Islands** — connected groups of positive samples (4-neighbour flood). No size clustering:
  a sub-24mm neck simply leaves no positive samples, so the area falls apart on its own. Scale-
  dependent by construction: the same duck is two islands small, one island large.
- **Depth masses** — the same mesh thresholded at the mass-depth dial: regions that survive
  16mm (default) of clearance. Limbs and slivers die shallow; true masses survive. This is how a
  CONNECTED shape with a waist (crescent, wide-necked duck) still reveals its parts.
- **Deepest-point centres** — each island's and mass's centre is its maximum-clearance sample,
  guaranteed inside the material (a crescent's centre sits in its arc, never the concave void).
- **Smooth outlines** — marching squares with linear interpolation traces where the clearance
  crosses the level; each traced ring is then densified (one midpoint per edge) and every point
  **snapped onto the exact offset curve** (`snapToIso`: two Newton steps on the signed-clearance
  field, stopping within 0.02mm), so drawn edges follow the true edge offset, not mesh facets.
- **Grade** — this map is measurement-grade, used for display and the centring score only.
  Magnet legality is ALWAYS the exact per-point integer test.

## 6. The guard (`grid-origin-separation.test.ts`) — 12 checks

1. **Portable** — no module file imports React/Next/CSS. *Prevents the engine growing UI roots.*
2. **Import allow-lists** — each module file may import only its named sources. *Prevents layer
   leaks (e.g. logic reaching into geometry).*
3. **Page reaches only the door/spec/bridge.** *Prevents the shell binding to internals.*
4. **Modules never import from the app.** *Keeps the engine portable.*
5. **SPEC is values only** — AST check: no functions, no arithmetic. *Values stay declarative.*
6. **LOGIC does no geometry** — bans hypot/sqrt/trig/predicates there. *Policy stays policy.*
7. **The page computes nothing** — bans geometry calls in the shell. *Drawing only.*
8. **Page carries no released value as a bare literal** — every spec number ≥10 is tracked; the
   page must use identifiers. *One write-route for law values.*
9. **Modules don't restate released values** either. *Same, engine side.*
10. **Law sliders pin their bounds to spec identifiers** (padding, snap step). *Bounds can't drift.*
11. **Determinism** — same shape, size, values → byte-same layout. *No hidden randomness.*
12. **The square standard fixture** — 24→1, 72→2×2, 120→3×3 (belt keeps 8). *The canon answers
    as an executable regression gate.*

## 7. Known open items & discrepancies (honest register)

**Awaiting Dan's ruling / calibration**
- **Perimeter belt admits non-edge magnets** in some layouts (Dan flagged 2026-08-19: peripheral
  selection "must be along the edge extremes only"). Queued after centring.
- **The band gate wording** — `isHolding` requires zero loose-material points, so a band can show
  a perfectly seated layout under a "nothing fully fits — best seated shown" banner. Two meanings
  of "fit" collide; design ruling open (options: silent gate / seated-is-fit / graded gate).
- **Mass depth (16) and balance tie (2mm)** are engineering defaults — the dials exist precisely
  so Dan can calibrate them.

**Code discrepancies found while cataloguing (not fixed — reported)**
- `computeGrid`'s doc comment still says "Sweep the lattice phase on the 12mm increment"; the
  ruled default is 1mm. Stale comment only — the code uses `PHASE_STEP_MM = 1`.
- `GridResult.ok` / `issues` (and `verdictIssues`) plus `edgeRangeMM` are computed every solve
  but **no surface consumes them** since the verdict banner was removed. Dead weight candidates.
- `grid.flaps` is not drawn anywhere (no red edge since the verdict cut); it only feeds the band
  gate via `flaps.length`.
- `centeringRef` tests seat-in-mass against the mass's **bounding box**, not the mass region —
  a seat outside a concave mass but inside its box can qualify it. Approximation; fine for
  compact masses, worth knowing for L-shaped ones.
- On large shapes a balance distance can exceed 200 score units (one coverage bucket), letting
  centring outweigh one 2mm coverage step — the terms are weights, not a strict hierarchy.
- In band mode the pinch-zoom gesture still adjusts the (hidden) free-slider size — a dead
  gesture there.
- `massDepth` is sent unconditionally (no per-control enable checkbox), unlike flap and placement
  step which have LabRow enables — inconsistent control pattern.
- `page.tsx`'s header comment still calls the file "grid-lab — Session 59".
- **Perf note:** `safeSegments` runs inside every `computeGrid`, so a band walk at 1mm snap step
  measures the island map once per size (~50–100 times per walk).
