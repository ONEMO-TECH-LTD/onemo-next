# v3.5.4 brief — permanent product result

Read this before planning, building or reviewing v3.5.4. Execution details are valid only when they deliver this result.

## Directive

Build one calibratable magnetic-grid engine that automatically finds the layouts Dan can find manually.

Given any supplied shape, selected Centre rule and admin settings:

1. **Centre:** lock each candidate magnet group to the governed anchor. It cannot float to find an easier fit.
2. **Fit:** keep every magnet disc inside the shape and find the tightest practical group fit without crossing the contour. Tangency may happen; it is not mandatory.
3. **Scale:** independently within each band, search the configured sizes and grid registrations, return every distinct lawful layout from the lowest fitting magnet count upward, and mark one preferred layout without hiding the others.

**Free mode** must correctly recognise and report the layouts available at the selected size.

## Acceptance

If Dan can produce a lawful layout manually using the same controls, the automatic engine must find and show it. It must never report “no fit” while that layout exists inside the configured search.

Every solver setting is editable in the admin dashboard and owned only by `src/lib/magnetic-grid/spec.ts`. No hidden constants, scoring, invented law, alternative solver or duplicated decision path.

Reuse and rewire the proven Centre, geometry, registration, worker, cache and UI bodies. Write only the missing candidate enumeration, group Fit measurement and three-law reduction.
