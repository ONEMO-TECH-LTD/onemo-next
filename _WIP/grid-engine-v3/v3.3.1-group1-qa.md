## Blocking findings

### 1. `productionReady` can still be forged by deleting assumption strings

`profile-schema.ts:133` treats an empty `engineeringAssumptions` array as proof that production inputs exist. `ProductProfile` has no required Frames, Fulfilment or Regression sections, although `02-logic-engine-spec.md` §4.2 requires them. It also cannot carry the complete approval/source evidence required by §4.4.

Reproduction against the repaired build:

```text
clone createReferenceProfile()
delete profileHash
set productionReady=true
set engineeringAssumptions=[]
registerProfile → ACCEPTED
```

Required repair: a production profile must positively contain and validate every required executable production section and value. Absence of unresolved-text markers is not evidence of completeness. Add a regression that clears the assumption strings and still fails because the required production inputs are absent.

### 2. Pattern-to-population membership is hard-coded to modulo 2

`profile-schema.ts:103-106` checks only whether all pattern coordinates share parity modulo `2`; it never uses the referenced population's `strideCells`. `frames-registration.ts:18` then converts cells directly and also does not enforce population membership.

Reproduction:

```text
clone createReferenceProfile()
delete profileHash
set grid.nodeStrideCells=3
set grid.populations[0].strideCells=3
leave the stride-2 pattern coordinates unchanged
registerProfile → ACCEPTED
```

Required repair: validate every pattern against its referenced population's actual stride and permitted relative residue/origin model. Add stride-3 rejection and valid-stride controls. This is the §4.3 invariant that every pattern point lies on a permitted population; it is separate from Group 4's later parity enumeration.

### 3. The claimed complete mechanics registry stops at M08

`profile-schema.ts:5-14` defines “complete” as M01–M08. The governing `onemo-mechanics-v1` registry in `02-logic-engine-spec.md` §11.2 contains M01–M10; M09 is canonical discrete identity and M10 is final registration identity. `ProductProfile.mechanics` has no typed representation for their complete rules, and the current reference profile is accepted with only M01–M08.

Required repair: the approved profile must encode or otherwise positively bind and validate the complete M01–M10 registry, including the M09/M10 ordering contracts. Do not falsely label the eight mechanical-score rows as the complete registry. Group 4 may implement their runtime use, but Group 1 must reject an incomplete production profile now.

### 4. Provenance validation proves only that one arbitrary string exists

`profile-schema.ts:131` accepts `{ONLY: "one unscoped note"}`. Section 4.4 requires every product-value field to carry decision/status/evidence trace. The current `Record<string,string>` shape cannot establish coverage.

Required repair: define the required provenance keys/records and validate coverage of every product-owned profile value. Add a regression showing that one generic entry cannot approve a profile.

**Sufficiency — partial:** safety rounding and hash authority are closed. Executable/production profile authority remains open on required-section presence, population membership, complete mechanics identity and provenance coverage.
