## Blocker 1 — “server verification” executes in the client bundle

`page.tsx` is a client component (`line 1`). It imports `verifyOnServer` and the current resolver (`lines 17–30`) and calls them directly in the click handler (`lines 327–333`). `server-verifier.ts` is only a synchronous wrapper around `verifyEngineManufacturingSpec`; it has no server-only boundary.

Independent production-build evidence:

- `next build` reports `/grid-engine` as static;
- the route folder contains no server action or route handler;
- the emitted `/grid-engine` browser chunk contains `MANUFACTURING_OFFER_MISMATCH` and `PHYSICAL_TOLERANCE_POLICY_MISSING`, proving the manufacturing verifier shipped to and is wired to run in the browser.

The live reference profile returned no offers, so the Playwright interaction could not execute certification, persistence or verification at all. This does not satisfy the Group 6 requirement to verify again server-side before production handoff.

Required correction:

1. Put parse, pinned profile/artifact resolution and `verifyOnServer` behind a real server-only boundary under the existing `/grid-engine` seam. A server action is the smallest fit; do not add another UI route or panel.
2. The client sends the serialized canonical spec and awaits the server result. It must not import the resolver or verifier.
3. Add a host regression proving verifier code/failure strings are absent from the client chunk and that the server boundary rejects a tampered or non-offered spec.

## Blocker 2 — the host silently changes source geometry under unresolved PD-35

The audited route sends `engineOutline(outline)` rather than the traced outline (`page.tsx:318–325`). That helper is v3.2 code driven by `DEFAULT_LAW.maxRungMM` and RDP simplification (`trace-cutout.ts:51–63`). It is not part of the v3.3 profile or intake contract.

Independent live evidence on PILL:

- displayed traced outline: 3,796 vertices;
- v3.3 canonical source ring: 34 vertices;
- the input was under the reference profile's 4,096-vertex limit, so the route changed a source the engine could accept instead of reporting or preserving it.

R3 Compute explicitly says PD-35 must measure/report and must not silently simplify; ownership of any pre-simplification remains unresolved (`01-compute-engine-spec.md:35,76,643`; `00-system-contract.md` PD-35).

Required correction:

1. Remove `engineOutline` from the v3.3 submission path. Submit the validated traced contour unchanged apart from the declared axis/centering adapter.
2. Preserve `RESOURCE_LIMIT_EXCEEDED` for over-budget input until PD-35 assigns an owner and limit. Do not make POKE1 pass by silently importing v3.2 geometry policy.
3. Add two host-boundary regressions: a within-budget contour preserves its complete canonical source identity; an over-budget contour fails explicitly without simplification.
