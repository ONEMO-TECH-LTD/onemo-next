calibrated judge. Three-part separation holds: `compute/` = math only, `spec.ts` = values only

## 2. Honest gap spectrum vs the v3.3 blueprint

**Substrate (cannot be tuned in, needs the new kernel):**
- G1 · Continuous feasible-region registration — placement solved exactly as
  `A ∩ ⋂(safeCore − offset_k)` instead of a 2mm sweep. Correctness (provably no missed seat)
  AND the entire performance story: v3.2 solves in 2–20 s; product target is ≤16 ms all-band.
- G2 · Certified conservative approximation — error envelope so a narrow valid seat can never
  silently vanish (we shipped this bug class twice: 5mm outline, 8mm sweep).
- G3 · Tolerance/quantum discipline in the judge — float compares + coarse buckets vs certified
  intervals; knife-edge flips (maxSide 28 vs 29) currently decide silently.

**Judgement quality (retrofittable into v3.2 incrementally):**
- G4 · Region hierarchy + persistence (multi-clearance components) — Dan's "major mass /
  marginal / connector" made computable; replaces template heuristics for multi-lobe shapes.
- G5 · Mass-aware cap moments — integrate the material hanging beyond the anchor hull instead
  of bbox distances (the butterfly-86mm-bottom bug class, solved principled).
- G6 · Constructive canonical parity seat (odd→node-on-centre, even→spacer-on-centre) proposed
  explicitly, not just preferred by buckets.
- G7 · Machine-readable rejection reasons per size/band (bench self-explains escalations).
- G8 · Counterexample + boundary-fixture suite (R3 §13.3: 11 named cases, ±1-quantum fixtures).

**Product plumbing (v3.3 scope):** versioned hashed profiles with provenance · two-stage
ManufacturingSpec (engine spec + fulfilment completion) with artifact hashes · byte-determinism
identity · size/payload budget (engine ≤250KB, ≤16ms).

**What v3.2 has that the blueprint lacks:** the hold-physics coverage oracle (48mm reach,
exact edge intervals — nothing equivalent in R3), strip law, symmetry law, structure classifier,
band separation/stepping — and above all a **working, canon-validated judgement**; R3's whole
mechanics registry is proposed and untested, frozen on a 27-decision ballot.

## 3. /o-necessity — the MVP change (directive: complete v3.2 into a mobile-first, fast,
super-precise, portable engine for the Next.js effects-engine repo, powering studio +
manufacturing spec)

**Directive deliverables enumerated:** (a) mobile-first fast — ms-class solve in Safari/Chrome;
(b) super-precise — no missed/false seats; (c) portable — a package the effects-engine repo can
import; (d) powers the studio — sizes+layouts per band to the UI; (e) powers manufacturing
spec — exact reproducible output object.

**Probe of current state (not documents):** the engine is already dependency-light TypeScript —
`compute/` + `spec.ts` + `logic/` import nothing from React/Next; the only native dep is
Clipper2 (already vendored via v1's `offset.ts`). The judge's cost is 100% the size×template×
2mm-sweep loop (~10⁴–10⁵ engine validations per solve). The bench page is the only Next.js
coupling. Meaning: **portability is nearly free; speed and precision are the same single fix.**

**MINIMAL DIFF — three elements, everything else is drift:**
1. **Replace the sweep with continuous placement (G1, subsumes G2/G3 where it matters).**
   Compute each size's safe-core once (Clipper2 inward offset — already in-repo), intersect
   shifted copies per template = the exact feasible region; take the judge's pick inside it
   (mass-axis/canonical point), then exact-revalidate via v1's own `DiscLegal`-equivalent
   (`distanceToPreparedContour`) — v1's oracle stays the sole legality proof, per both our law
   and R3 §6.2. Judge ranking is untouched — same laws, same canon gate, ~10² fewer engine
   calls → the ms-class, mobile-first target. This is the ONE substrate element of v3.3 worth
   pulling forward, and it composes with the byte-verbatim core instead of replacing it.
2. **Package boundary:** lift `compute/ + spec.ts + logic/ + bridge.ts` as `@onemo/grid-engine`
   (pure TS + clipper2 wasm), consumed by the effects-engine repo; the bench page becomes its
   first consumer. No rewrite — the move/clone rule.
3. **ManufacturingSpec output:** serialize what the judge already knows per accepted solution
   (size, anchors mm, layout id, wraps, engine policy signature — v1 already hashes its law set
   as `GRID_ENGINE_POLICY_SIGNATURE`) into one canonical JSON object. The two-stage fulfilment
   completion stays v3.3.

**Justified beyond the baseline:** G7 rejection reasons (tiny; Dan asks "why" on every bench
review — pays for itself immediately). **Deliberately excluded from MVP:** G4/G5/G6 (quality
iterations on the calibration loop, not blockers), profiles/hashing/two-stage spec (production
hardening), backend probe TS-vs-WASM (Clipper2 is already the incumbent; probe only if the
budget fails), any new architecture, any rewrite of the v1 core.

**Necessity verdict:** no unnecessary elements — three changes + one justified extra.
**Sufficiency verdict:** delivers the directive in full — (a) via change 1, (b) via change 1's
exact feasibility + exact revalidation, (c) via change 2, (d) already delivered by the judge +
change 2, (e) via change 3. Not sliced: everything the directive names is covered; v3.3's
remaining scope (regions, moments, profiles, fulfilment chain) is explicitly deferred work for
Dan to schedule, not silently dropped.

## 4. Recommendation

Do NOT restart as v3.3-from-documents (the failure mode of both GPT tracks). Keep v3.2 as the
living oracle and pull exactly one substrate idea forward: **continuous placement**. Sequence:
MVP changes 1–3 in this worktree behind the existing canon gate (all 7 shapes must reproduce

bench → v3.3's remaining scope becomes incremental hardening of a shipping engine, and its

tolerance PD-38).
