# v3.5.6 magnetic grid — MVP execution contract

**Status: proposed for Dan + QA approval. No MVP code may start until both approve this file.**

This is the only execution plan. `v3.5.6-current-brief.md` remains product authority and
`v3.5.6-pipeline-brief.md` remains pipeline authority. `grid-lab-architecture.md` and the move matrix
are implementation history, not competing task lists.

## 1. What we are building

One headless magnetic-grid pipeline:

```text
shape
  → segment its usable material
  → classify the ordered grid frame
  → find every matching catalogue layout and view
  → centre and tightly wrap each full rigid magnet population
  → return every attempt, unsorted and unhidden
```

The pipeline replaces the current search-and-pick engine. It does not guess a winner. It does not
silently drop magnets. It does not rank, score, apply perimeter/corner/96mm filters, reject an answer
because it wrapped into another band, or show a calibration witness as a lawful answer.

The same pure call runs without React, a worker or a browser. The worker transports and caches the
request. The bench renders exactly what the call returned.

## 2. The problem this fixes

The current code does not run that pipeline:

- `units/classifier.ts` measures the outer box, clamps both axes to `1..5`, and is not consumed by the
  engine.
- `grid-magnet-library-catalogue.ts` filters on an invented three-family rule and cannot return the
  view needed to use a canonical portrait record on a landscape shape.
- `units/layout.ts::registerLayout` creates four registrations, silently keeps one by magnet count,
  then `applyCoverage` removes magnets before wrap.
- `grid-magnet-wrap-compute.ts` scans sizes, derives layouts from the old search, rejects wrapped
  results by the requested band, sorts them, and selects a calibration witness.
- `units/judge.ts` sorts and supplies a default landing.
- `solve.worker.ts` contains segmentation, classification, centring, band logic, caching, default
  selection and response shaping. It is an engine, not transport.
- padding is defaulted or clamped in units and callers instead of resolved once to the released 12mm.
- the page still sends old product filters and displays one selected answer rather than the raw ledger.
- the library producer has changed, but the tests and oracle still describe the retired populations.

Measured on the current working tree on 2026-08-29: the three relevant test files report **109 passed,
31 failed** — 28 stale library tests, two stale architecture gates, and one stale oracle fixture. This
is not a cleared library or a trustworthy base for the engine cutover.

## 3. Locked product rules for this MVP

1. **The pipeline is the only filter:** segmentation → classification → layout → wrap.
2. **Centring remains the governed anchor:** it chooses among lawful wrap origins; it never removes a
   candidate. Existing six modes and governors stay available. The class-to-centring mapping is not
   invented in this MVP.
3. **Classifier source:** ordered frame from the union of all live masses. Never outer box, governing
   mass, hardcoded family, aspect ratio or a five-line ceiling.
4. **Neutral classification:** every catalogue candidate matching the ordered frame is returned with
   its evidence. Cross-class ambiguity is explicit, never silently resolved.
5. **Catalogue:** square and rectangle are generated full-frame canon. Diamond and triangle are
   approved presets. One canonical record is stored; matcher returns `{ entry, view }`.
6. **Mirrors stay:** a scalene mirror is a different magnet set even when the physical part can be
   turned over.
7. **Board:** fixed 384×480mm legal span. At pitch 24/48/96 it holds 17×21 / 9×11 / 5×6 positions.
   Nothing below the board may cap the engine.
8. **Band:** catalogue data and result label, measured on legal magnet span every 48mm through B11.
   A requested band may bound which frame is examined; it may not reject a layout whose exact wrap
   lands in another band.
9. **Wrap:** full rigid population in; tightest lawful size and minimum necessary shift out. A null
   wrap is evidence. It never authorises dropping a node. Holes remain material boundaries.
10. **Padding:** released 12mm resolved once at the public door. Units receive a required value and
    do not default or clamp it.
11. **Output:** every attempt, in production order only, with no sort/default/auto-selection. Each
    attempt names classifier evidence, catalogue identity and view, requested and placed nodes, exact
    wrapped size, actual band and outcome.
12. **No dual engine:** the old path is deleted in the same cutover that wires the replacement.

## 4. Minimal diff

The smallest complete delivery is:

1. Repair the existing tests and oracle to describe the catalogue already landed.
2. Complete the existing classifier and catalogue matcher; do not add another classifier framework.
3. Turn the existing public door, `grid-magnet.ts`, into the pure pipeline; do not add a second door or
   a new `pipeline/` ceremony folder.
4. Use the existing bridge as the UI adapter; reduce the worker to transport/cache; make the page render
   the returned ledger.
5. Delete the old search, judge, selection and compatibility files once their last real caller moves.

No separate “move the magnet-fits-here test” task exists. That work is already present in
`units/layout.ts` as `makeSeatPredicate`, `makeCircleSeatPredicate` and `makeContourSeatPredicate`.
Scheduling it again would be false work.

## 5. Execution tasks

### T0 — Restore catalogue truth and trustworthy gates

**Purpose:** make the landed canon/preset producer testable before engine work starts.

**Production code:** none unless a rewritten invariant exposes a real producer defect. Such a defect
returns to proposal/approval; it is not repaired silently inside this task.

**Edit:** existing library test, catalogue oracle fixture/test, and existing separation gate only.

**Required result**

- Square/rectangle frame sets derive from 17×21 / 9×11 / 5×6 pitch-aware board limits.
- One full population per canonical frame; square 4×4 contains all 16 nodes.
- Diamond/triangle assertions cover their approved full preset populations, not deleted
  `perimeter`, `corners` or `perimeter-96` layouts.
- Catalogue V3 record sets are 254 at 24mm, 92 at 48mm and 47 at 96mm; every record has a band and none
  exceeds 384×480mm.
- Manifest and oracle identity are keyed by `id@pitch`; obsolete population cases are removed from the
  fixture rather than tolerated.
- The numeric-literal scan and “spec contains no arithmetic” gate are replaced by semantic checks for
  released pitches, board dimensions, band repetition, padding ownership, retired controls and import
  boundaries. A font-size `11` cannot fail a physical-law test.
- No test is merely renamed around deleted behavior; retired tests are deleted.

**Done when — paste exact output in the commit**

- relevant three test files: zero failures and zero skipped tests;
- full suite: zero failures; any pre-existing skip named explicitly;
- TypeScript: zero errors;
- scoped lint over every touched file: zero errors and warnings;
- catalogue count/band/board probe prints the three expected count rows;
- mutation: add one invalid record, remove one valid record, publish a null band, or exceed the board —
  each independently kills a relevant test.

**Gate:** lead self-review, then adversarial QA. T1 does not start before QA-CLEAR.

### T1 — Replace guessing with the complete raw MVP pipeline

This is one product delivery. The substeps are build order, not separately landable half-engines.

#### T1.1 Classify the material

- `units/segment.ts` remains the one producer of legal islands and masses.
- `units/classifier.ts` consumes the union bounds of all live masses and the requested frame/band context.
- Remove `AxisClass = 1|2|3|4|5`, the countdown from five, outer-box classification and
  `shapeFamilyOf`.
- Return the ordered frame and measurement evidence. A dead 30mm arm and a live 50mm arm must separate
  into the ruled 3×3 and 3×6 counterexample.

#### T1.2 Match every certified layout

- Replace `catalogueCandidates(outer, pitch)` with a matcher over pitch + ordered frame.
- Return every `{ entry, view }`; do not filter on family, aspect or a winner score.
- Prove `ROTATION_VIEWS`/`D4_VIEWS` through `transformLayout` before relying on them.
- Preserve cross-class identity: the same 1×1 node set can remain distinct square and diamond products.
- An unknown frame returns an honest empty candidate list.

#### T1.3 Run one pure headless door

`grid-magnet.ts` becomes one serialisable call. For each request it:

1. resolves the released padding once;
2. segments the supplied contour, preserving holes;
3. obtains the governed centre using the existing centre mode/governor;
4. classifies the ordered frame;
5. matches every catalogue entry/view for that frame;
6. hands each entry's **full unchanged population** to `wrapGroup`;
7. labels the result by its actual wrapped band;
8. returns every success and failure as an unsorted attempt ledger.

The public response must be serialisable and sufficient for both tests and the bench. No browser,
worker, React type, callback or function may cross the door.

#### T1.4 Cut over the real caller and delete the old engine path

- `solve.worker.ts`: request/response transport and cache only.
- `grid-magnet-bridge.ts`: request construction and view-model shaping only.
- `grid-centre/page.tsx`: controls and rendering only; no classification, layout, wrap, band or default
  selection logic.
- Bench: one card/chip per attempt. Show class/frame/evidence, entry/view, requested and placed count,
  exact wrap size, actual band and outcome. **Never auto-select even when only one attempt succeeds.**
- Remove old controls the new engine does not read; do not invent replacements.

Delete after their last production caller moves:

- `grid-magnet-wrap-compute.ts`;
- `units/judge.ts`;
- `grid-magnet-class.ts`;
- the remaining compatibility shells in `grid-magnet-compute.ts` and `grid-magnet-logic.ts`;
- `registerLayout`, its four-parity/max-count winner, `applyCoverage`, `fallbackRevealSizes`,
  `bestSeatedCandidate`, `defaultLanding`, `orderOffers`, band rejection and witness publication;
- the two segment decimators from the correctness path;
- every unit-level padding fallback/clamp and the square `FIELD_POSITIONS_PER_AXIS` ceiling.

Useful display-only bodies move to the existing bridge rather than keeping a retired compute bucket
alive. Every deletion is proven by real production-reference search, not a hand-maintained name list.

**Done when — paste exact output in the commit**

- plain Node/Vitest call, no worker/browser, returns the complete attempt ledger;
- 168mm square exposes all four lawful registrations to the ledger instead of one max-count winner;
- landscape rectangle receives the canonical portrait entry with the returned view;
- cross-class frame returns every candidate and names ambiguity;
- full population reaches wrap byte-for-byte; mutations that drop one node, sort attempts, select a
  default, reintroduce family filtering, reject by wrapped band or default padding each kill a test;
- supplied donut keeps its hole through segment and wrap;
- requested/placed/omitted counts are arithmetically consistent for every attempt;
- zero production references to every deleted symbol/file;
- full suite, TypeScript, scoped lint and diff check clean with skips named;
- exact-head live bench across pitches, square/rectangle/diamond/triangle and holes: returned ledger
  equals rendered attempts, no hidden card, no auto-selection, no overflow and no console error;
- Duck check: record whether 3 at ~143mm, 4 at ~147mm and 6 at ~192mm are present in the raw ledger.
  Presence is evidence about MVP coverage; absence is a finding. The MVP is not allowed to add ranking
  just to make them win.

**Gate cadence:** proposal approval → build complete T1 → lead gate 1 with source, mutation and live
evidence → adversarial QA gate 2 in its own checkout and live surface → Meta intent/necessity gate → Dan
reviews the product-visible bench. No code-ahead across these gates.
