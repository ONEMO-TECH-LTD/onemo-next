# v3.5.6 magnetic grid — MVP delivery plan

**Status: v1 — for Dan's approval. QA's eight-finding audit applied (seven agreed, one countered).**

**Scope of this contract.** This is Dan's authorised raw-MVP slice: segment → classify → layout → wrap.
It proves the pipeline works without a hidden selector. Scoring, the perimeter/96 selection, Fit-mode
completion and the current brief's §12 product acceptance remain later work and are not claimed here.

**The contract** (Dan, 2026-08-29): *"segmentation > classification > layout is the filter already,
we cannot apply anything here at all, wrap applies to that and this is MVP — no other filters must
be there at all."*

## THE PIPELINE — Dan's five steps, verbatim (16:29, the latest and controlling statement)

> *"the entire pipeline is the compute and selector because if each step is done it can arrive into
> result only within nerrow set boundaries:*
> *1. Class - filters the selection to classes*
> *2. Bands - provide defined anchors for measurement and ranges for limits - another filter*
> *3. Layout - the optimal layout found and attempted within shape*
> *4. Wrap - fine tuned the shape to fit optimal layout - anything falling off the layout is just
> omitted as not fitting the shape*
> *5. Next best - attempts to define other layouts that may fit the band/class and wrap law if we fine
> tune center, shift the grid vs shape panning it and rescaling it to adapt ... it must be adjusted to
> find min count > propose > find max count > propose and find if the optimal count based on the class
> canon fits > propose"*

**The MVP is steps 1–4.** Step 5, next best, is deferred by Dan's own scoping (16:15: *"step 1 -
segmentation > classification > layout is the filter already ... wrap applies to that and this is MVP
- no other filters must be there at all"*). The five steps ARE the filter; nothing else may narrow.

In plain terms, what each step does:

1. **Class** — read the shape's usable material and say which grid it is: 3 wide by 4 tall, and so on.
   Measured on the material that can actually hold a magnet, so a thin dead arm doesn't count.
2. **Bands** — the measurement anchor and the size range. The requested band says where to measure and
   what range to search; the band a result *lands in* is read off its wrapped size afterwards. A band
   never deletes a result for landing elsewhere.
3. **Layout** — fetch the layouts the library holds for that grid and attempt each one inside the
   shape. Looked up, never invented.
4. **Wrap** — shrink the shape onto each attempted layout to its exact gripping size. **A magnet
   position that falls outside the shape is omitted as not fitting** — Dan's ruling, twice (11:55,
   16:29) — and the omission is recorded on the result, never silent. The wrap law is untouched: what
   ships is tight, touching, never relieved.

**What you get at the end:** pick a shape and a band on the bench and see every layout the library
holds for its grid — each with its exact wrapped size, its magnet count, which positions were omitted
and why, which band it actually landed in, and whether it held at all. Unordered. Nothing hidden.

**Done means all five of these are true:**

1. Every attempt on the bench declares its own evidence: class, frame, layout, view, grid position,
   magnet count, wrap size, the positions the material refused, and the band it actually landed in.
2. The same list comes back from a plain test with no browser open.
3. Nothing in the code sorts, ranks or picks — proven by searching the names, not asserted.
4. The old millimetre-by-millimetre size search is deleted, not switched off.
5. The 168mm square shows four grid positions where it shows one today.

**Correction on the record (this revision):** QA had omission removed from the MVP entirely as an
invented mechanism, and I agreed. That overrode Dan's own ruling — *"anything falling off the layout
is just omitted as not fitting the shape"* — which is later and his. Omission is step 4's law, done
inside wrap on the real material, recorded on the result. What stays dead is the thing QA rightly
killed: guessing one position, dropping whatever misses there, and calling that the layout.

The library publishes one population per frame: full coverage. Square and rectangle are canon;
diamond and triangle are presets. Frames derive from the board in millimetres at the asked lattice.
The band has one owner and the page stops computing it. Catalogue v3, band never null.

- **AC — canon:** one population per frame, named `full` or `single`; no `perimeter`, `corners` or

- **AC — band:** every published record carries a band; an absent band throws at the producer; the
  page reads `materialized.bandId` and computes nothing.
- **AC — chips:** every frame chip reads its band at the asked pitch.
- **Evidence:** 24mm 254 records (17/204/9/24) · 48mm 92 (9/54/5/24) · 96mm 47 (5/15/3/24) · zero

## P1.1 — Read the shape, say which grid it is

Today it measures the outer outline's box, counts to five and clamps, and its only consumer is a
display readout — delete it and every answer is identical.

- **AC — measurement:** the ordered frame comes from the **union of all live masses**; never the
  outer box, never the governing mass. A 30mm dead arm and a 50mm usable one read 3×3 and 3×6.
- **AC — ceiling:** derived from the live band table. The `1|2|3|4|5` type, the countdown from five
  and the frame clamp are gone. There is still a ceiling — it is the board's, not a typed number.
- **AC — honesty:** return every catalogue entry/view on the derived frame. If several entries share a
  frame, return all of them with their distinct identities; **no count is frozen in this contract** —
  the classifier must grow when the catalogue grows, so a frozen count would fail a correct authoring.
  (Dated state note, not an AC: 10 of 69 frame groups at 48mm are cross-class today.)
- **Evidence:** the limb pair separates 3×3 from 3×6; a frame above the old five classifies; a current
  catalogue sweep proves every multi-entry frame returns all of its entries.

## P1.2 — Look the layouts up in the library

`catalogueCandidates` has no production caller and filters on the invented `fill < 0.68` family.

- **AC — key:** **pitch + ordered frame**, never the requested band. Band is a label on a result, so a
  request for B3 may not hide the same frame that wraps into B4. It returns every `{ entry, view }` on
  that frame; the family gate is deleted; `actualBand` is assigned only after wrap.
- **AC — orientation:** returns `{ entry, view }` — one canonical record, the matcher says which way
  round. A landscape shape receives the certified portrait layout.
- **AC — views proved:** `ROTATION_VIEWS` and `D4_VIEWS` verified through `transformLayout` before
  use, not trusted from the literal.
- **AC — identity:** cross-class identity survives dedupe. The 1×1 node set stays two records —
  edge-up square and corner-up diamond are different certified products.
- **Evidence:** a landscape mass receiving a portrait record with the view named; the 1×1 pair intact.

## P1.3 — One way in, runs without a browser, old search deleted

One change, no dual path. This is the task that makes the pipeline real.

- **AC — the door:** `grid-magnet.ts` runs segment → classify → match → wrap → an **unsorted list of everything it tried**. No sort, no default landing, no witness, no judge.
- **AC — headless:** that door is callable from a plain test with no browser. The worker becomes
  transport and cache; the page reaches the engine through an adapter. This is the lane's stated
  deliverable and it is what makes "test it" mean something other than clicking the bench.
- **AC — placement and omission (Dan's ruling, mechanism settled):** seat the layout at the governed
  registration; test each position independently with the seat rule; omit what the material refuses;
  wrap the survivors to their exact tight size. `wrapGroup` stays whole-group-in, tightest-out — the
  per-position test happens at seating, with the same physical law as everything else. Every omission
  is recorded on the result. Dead: an arbitrary bbox-origin prefilter or any undeclared omission. Every governed node/gap
  registration is evaluated and reported before wrap.
- **AC — centring kept:** `units/centring` supplies the governed anchor. `heldAt`/`pickOrigin` only
  break ties among origins that are already lawful, so it filters nothing.
- **AC — raw registration:** layout emits **every** non-empty node/gap registration with its phase.
  Only the count/canonical/press winner at the end of registration is deleted. The seat predicates and
  the four-registration enumeration stay — they are what the 168mm-square proof below measures, so
  deleting `registerLayout` wholesale would make that proof impossible.
- **AC — the old lane gone:** zero production references to `grid-magnet-wrap-compute.ts`,
  `units/judge.ts`, `defaultLanding`, the registration winner, `applyCoverage` in the raw path,
  `fallbackRevealSizes`, `bestSeatedCandidate`, `grid-magnet-class.ts`, `shapeFamilyOf`,
  `grid-magnet-compute.ts`, `grid-magnet-logic.ts`, both stride decimators, the dead two-magnet
  floor, the silent invalid-band fallback, both contact thresholds.
- **AC — padding:** one resolver at the door returning the released 12. No unit defaults it, none
  clamps it. It is resolved at eleven sites today, each of which also raises a smaller value to 10.
- **Evidence:** a plain no-browser test returning that list, pasted · `grep` output proving each
  deleted symbol has zero production references, by name · the 168mm square showing **four**
  registrations where it shows one · suite, typecheck and scoped lint clean.

## P1.4 — The bench shows every layout found, unsorted · **DAN GATE**

Removing what Dan can see is his call, not ours.

- **AC:** one card per attempt — class, frame, magnet count, wrap size, **which positions were omitted
  as not fitting**, the band it actually landed in, outcome. Omission is step 4's own law (Dan: "anything
  falling off the layout is just omitted as not fitting the shape") and the card must declare it —
  an undeclared omission is a hidden filter.
- **AC — one path:** the manual and band controls run the same pipeline. Product law §1: *"Free/manual and
  automatic/band solving use the same inputs, laws and verdict. Manual is not a bypass."*
- **AC:** one card for every attempt returned. **None is selected, promoted, sorted or hidden** — a
  single result is still a raw result, and selecting it is a hidden default. The band shown is the one
  the result actually wrapped into.
- **AC:** no ordering, no default pick, no control the engine does not read.

- **Evidence:** the exact tree served, commit named, swept across pitches, classes and bands, with
  captures. Per shape: the list, and where Dan's answer sits in it.
