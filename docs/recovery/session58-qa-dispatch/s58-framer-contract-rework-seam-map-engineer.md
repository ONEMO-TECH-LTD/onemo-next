## A root cause — confirmed from current source

- Project component directory has no TSX component (`.gitkeep` + `.onemo` only).
- The visible `DemoButton` is global.
- `page.tsx:3925-3930` opens only `root === 'project'`; global edit emits the phase toast.
- `authoring-session.ts:26-28` refuses non-project roots and `editor-authoring/handler.ts:10` hardcodes `project-main`.
- Blank creation was removed/deferred (`page.tsx:3922`).

Therefore double-click works as coded but has **no editable target**: the only visible component is deliberately refused, and there is no project/blank fallback. Fixing reachability requires Dan-approved blank creation and root-aware inventory/session plumbing. What double-click on a global/library component must do remains **SOURCE-PENDING**; this map does not infer it.

## Cross-cutting transaction/history contract inherited by every row

1. Every durable mutation starts from expected graph revision, exact per-file source hashes, and the environment fingerprint; it obtains the owning store lock(s) before prepare.
2. CompilerAdapter produces staged bytes plus exact graph forward/inverse patches. Strict jailed SourceProjection reparse and semantic typecheck pass before any file install.
3. Single-root mutations use one durable participant. Cross-root mutations use one discoverable coordinator: every participant and full preimage/after-image is durable before the first install; one terminal decision governs all roots.
4. Source, sidecar, metadata, and history install under the same lock/decision. Failure or restart restores/verifies byte images from disk evidence alone; history never sits outside the transaction.
5. `SourcePropertyRef`, `InteractionOverride`, component/variant/instance IDs, and inherited membership survive forward and inverse replay. Undo restores lineage—not only visible values.
6. Every mutation slice proves commit, named refusal with zero writes, reload, undo, crash recovery, dead-end behavior, and the correct single-root/cross-root boundary. Read/navigation/clipboard/preview operations create no history and mutate nothing.
7. Headed E2E and mutation probes run only in a throwaway worktree with captured/restored baselines; they never run against the authoritative build worktree.

## Corrected dependency/build order

1. **Entry:** A reachable blank/root-aware path and infinite edit-in-place canvas; global double-click waits for source-exact AC.
2. **Foundation:** K inner-content selection/edit transaction primitives, then L component Style inspector.
3. **Lifecycle/organization:** B component lifecycle plus H dedicated Components topology, categories, folders, and root moves.
4. **Variants/states:** C observed variant/Primary override operations, then D Hover/Pressed state semantics.
5. **Props:** E typed property controls and instance values.
6. **Interactions/preview:** F evidence-bound transitions/New Event, then G preview runtime.
7. **Instances:** I insert, Trigger, Edit Component versus Go to main, detach, replace, and replace-all.

No dependent slice dispatches before its source-pending decisions and prerequisite seams are frozen.
